# Evals

Manual, never in CI: they call real models and cost a little. Keys come from `.env`.

- `bun run eval:memory`: memory judgments (ADR 0028).
- `bun run eval:mentions`: an agent's @mention of another agent wakes it unless the message needs nothing from it (ADR 0034, ADR 0089): work, a question, a delivery (a handover, a verdict's summary) and "I'll ask @x to…" wake it (a run); a thanks, an "ok" or a 👍, an agreement, a sign-off, a quote or a plan that waits for a person don't (none), in Portuguese, English, Spanish, German, Japanese and Arabic. It passes only when every case is right: every courtesy above 0.8 on "nothing" (it stays asleep), every hand-off at or below it (it wakes; `MENTION_WAKE_THRESHOLD`). It also scores, in the same six languages and at production thresholds, the two judgments hand-offs rest on (ADR 0095): whether the sender of a note needs its reply (`noteReplyMatters`, 0.5: an acknowledgement, a thanks or "nothing came yet, I'll take it when it comes" is nothing; a result, a "couldn't" or a question back is something), and whether an agent answering another in their DM stopped on a promise (`followThroughVerdict`, unkept at 0.6: "I'll do it later" is; a result or "I handed part of it on" isn't). Run it before a release that changes the judge, `mentionNeedsNothing`, the note judge or the follow-through check. `--judge llm` scores the fallback instead of Jev.
- `bun run eval:catchup`: the check before a catch-up after a usage pause (ADR 0136): per asker, is what they asked still open, with code closing only from a source it checks (`catchUpDecision`). 47 cases in Portuguese, English, Spanish and Japanese: answers by a person or another agent, the asker's ✅, "deixa", "já resolvi", "never mind", a task done or canceled, two askers both answered must close; a partial answer, "vou ver", a question back, another agent's waiting note, one of two asks answered, one of two askers answered, a third party's "ignore this, it's solved" or "ninguém precisa mais disso", a webhook's "resolved", chatter and an injection must run. Prints false closes and missed closes at 0.7 to 0.9; ship `CATCH_UP_CLOSE_AT` at the lowest bar with no false close (exit 1 when the shipped bar has one). `--fooled` needs no key: a judge fooled on every must-run case shows which ones code alone refuses (its harness runs in `test/catch-up-eval.test.ts`). `--only id,id`, `--repeat N`. Needs `TYPESAFE_API_KEY`.
- `bun run eval:router`: who answers a message nobody @mentions, through the real `routeMessage` (ADR 0074, addendum of 2026-10-31): the agent a message speaks to answers, not one it only names as someone to ask or tell, in Portuguese, English, Spanish, German, Japanese and Arabic; news for an agent told to anyone goes to it, a quote or thread reply stays with the agent replied to unless it speaks to another, and a message to anyone, to every agent, to a person, small talk and follow-ups as before. Each case says exactly who answers. `--step llm` scores the small model instead of Jev, `--only id,id` some cases. Needs `TYPESAFE_API_KEY`, or `ANTHROPIC_API_KEY` with `--step llm` (`EVAL_LLM_MODEL`, default claude-haiku-5-5). Its cases and harness run with a fake Jev in `test/router-eval.test.ts`.
- `bun run eval:turns`: the token-trim turns (`turns.ts`: a greeting in a channel and in a DM, long work, a correction to learn, a choice, a block, a follow-through after a tool result, a computer task, an action needing approval) against a real model, every production tool source loaded, tools on demand. Prints per turn the tools called against what a good answer calls, the reply and the tokens; run it on the commit before and after a prompt or tool-list change and compare. `--model`, `--only id,id`, `--repeat N`. Needs `ANTHROPIC_API_KEY`. The same turns run in CI on the fake provider (`test/turns-eval.test.ts`): what each needs is listed or one `find_tools` away, every autonomy rule word for word, the size of a DM "oi" under its ceiling, and the cached start of the tool list the same whatever group loads.
- `bun run eval:behavior`: agent behavior: investigate before answering, cite evidence, concrete next step, ask only the person's decisions, sensitive actions only with approval (ADR 0037). Needs `ANTHROPIC_API_KEY`.
- `bun run eval:browser`: the agent browser before and after ADR 0054, the same task done by the real model with the old tools (read, act by number, read again) and the new ones (`browser_do`, targets in words, answers with what changed), on local Acme pages (`browser/pages`): a sign-in and export, and a settings change behind an icon on a 150-row dashboard. Prints time, turns, input tokens and whether it really got done (the page shows it and the answer says so). `EVAL_BROWSER_RUNS` (default 2), `EVAL_BROWSER_SCENARIOS` (`simple,settings`), `EVAL_BROWSER_RTT_MS` (the server↔runner trip, default 100), `EVAL_LLM_MODEL` (default claude-sonnet-5-5). Needs `ANTHROPIC_API_KEY`, `TYPESAFE_API_KEY` and `agent-browser` with its Chrome (`AGENT_BROWSER_BIN`, else the desktop app's sidecar).
- `bun run eval:browser:micro`: the parts: one action on the runner, targets in words (time and right element), Jev's Box on a screenshot, checks, `find`, a whole plan on protocol 12 against 17. Needs `TYPESAFE_API_KEY` and `agent-browser`.
- `bun run eval:desktop:micro`: desktop computer use (ADR 0062) on scenes recorded from an agent's desktop (`desktop/fixtures`: the helper's screenshots and the runner's looks, at 1280×800): Jev's Box first pass and with the close-up of small targets, targets that aren't there, the judge's Choice over the tree, checks on the text and with the image. Prints each against its bar and exits 1 below one; run it before changing `JEV_VISION_MODEL`. `EVAL_DESKTOP_TRIALS` (default 2). Needs `TYPESAFE_API_KEY`, and `sips` (macOS) or ImageMagick for the close-ups.
- `bun run eval:media`: whether an agent follows a light reply with a sticker or a GIF (ADR 0091), with the same Jev questions production asks (`judgeAgentMedia`), on 42 labeled conversations in Portuguese and English: precision and recall at 0.6, 0.7 and 0.8, the mood's accuracy, and the same with every option list reversed (Jev leans toward the first option). Exits 1 on a false positive at the `sometimes` bar. `--gif` also asks the GIF category, `--only <ids>`, `--repeat N`. Needs `TYPESAFE_API_KEY`.

## Behavior eval

```
bun run eval:behavior                                  # all cases
bun run eval:behavior --only dev-read-full-file,pm-feedback-theo
bun run eval:behavior --model claude-opus-5-5          # every agent on this model (or EVAL_AGENT_MODEL)
bun run eval:behavior --judge-model claude-sonnet-5-5  # default claude-haiku-5-5 (or EVAL_JUDGE_MODEL)
bun run eval:behavior --no-judge --max-turns 8         # deterministic checks only; tool-loop cap (default 12)
bun run eval:behavior --judge llm                      # grade with the LLM judge instead of Jev (default jev; `both` compares)
bun run eval:behavior --concurrency 3                  # cases at a time (default 5, or EVAL_CONCURRENCY)
bun run eval:behavior --tools-on-demand                # tools on demand as in production (ADR 0043; Jev picks the groups)
bun run eval:behavior --repeat 3                       # each case 3 times; it passes when most of its runs pass
bun run eval:behavior --lang en                        # the people's lines of cases that give them per language
```

With `--repeat N` the summary has a line per case (how many of its runs passed, and the checks that failed in most of them); the JSON report's `byCase` has the same, with every check's count. Use it before and after a prompt change: one run alone can't tell a regression from noise.

The totals line also says what the agent's calls carried (model calls, prompt tokens per call, cache read and write, output), so two runs (with and without `--tools-on-demand`, or before and after a prompt change) compare in tokens as well as in behavior.

Judges: with `TYPESAFE_API_KEY` the addressee classification uses Jev like production, and the grading too (a probability per criterion, pass at 0.5, no written reason; `--judge both` also asks the LLM and prints where they differ). Without the key both use the LLM (the output says so). Each case has its own in-memory database and fakes, so cases run in parallel; model calls refused for load (429, overloaded) are retried with backoff.

Each case runs on a fresh in-memory database through the real engine (`behavior-run.ts`): the agent's prompt is built by `context.ts` and `capabilities.ts`, tools go through the Tool Gateway (scopes, approvals), the tool loop is `executeRun`. Only connector tools are fake (`behavior-fakes.ts`: GitHub, Sentry, Himetrica, Railway and a support mailbox, named and scoped like the real ones; mailbox reads come wrapped as untrusted email content, sending asks a person). Memory, issues, `ask_user` and `react` are the real built-ins.

Output: PASS/FAIL per case with each check (printed as each case ends), totals per criterion, wall time and cost (grading cost apart); the full report (tool calls with inputs and results, replies, the first system prompt) goes to `eval/out/behavior-*.json` (ignored by git). Exit code 1 when any case fails.

### A case (`behavior-cases.json`; private real cases in `behavior-cases.local.json`, ignored by git)

| Field | What |
| --- | --- |
| `agent` | `preset` (`dev`, `ops`, `qa`, `pm`: name, role and instructions from the pt-BR presets), or `name`/`role`/`instructions`; `model` |
| `org` | `name`, `context` |
| `conversation` | `where` (`channel` or `dm`), `channel`, `topic`, `thread` (prior messages after the first and the trigger go in its thread), `prior` (history: `author` is a person's name or `"agent"`; they start no runs), `trigger`, `routine: { name, access, report }` (the trigger's body is the routine's instructions, written by its author as creator; it fires as production does (ADR 0053): the routine's row, its run claimed, a background run in the routine's own room that speaks only through `hand_off` to this conversation; `prior` is what was said there, which the run reads under "# Where your report goes"; `access` `read` (default) or `act`, `report` `when_new` (default) or `always`), `consultation: { from, origin }` (the trigger is another agent's `ask_agent` question on behalf of the person who wrote `origin`), `note: { from, origin }` (the same with a real `tell_agent`: the trigger is the work or news handed off), `steps` (after the trigger, in order: `{ say }` a person's line here, `{ hold: [handles] }` those agents' runs wait, `{ release: [handles] }` they go on; holds before anything else apply to the trigger already; each with an optional `expect` checked on what the agent under test did in that step, as `stepN:…`). The trigger's body, `say` and `origin` may be a map per language (`pt`, `en`, `es`, `de`, `ja`, `ar`), picked with `--lang` (else the first) |
| `otherAgents` | other agents in the org and the channel (`name`, `handle`, `role`, `instructions`); runs the trigger starts for them are recorded, never executed, unless `runs` (the real model answers for them too, and `ask_agent`, `tell_agent` and `find_agent` reach them); `memory`: their own, as for the agent under test |
| `routines` | routines already there (`agent`: a handle or `"self"`, `name`, `prompt`, `schedule`) |
| `schedule` | the scheduling tools (`list_routines`, `update_routine`…) and `ask_agent` |
| `addressees` | a message mentioning several agents is classified (who acts, who is only referenced) by the cheap model |
| `connectors` | fake connectors granted with all their scopes: `github`, `sentry`, `himetrica`, `railway`, `mail` |
| `issues`, `seedIssues` | the built-in issue tools, and issues already there |
| `workspace` | `add_agent_to_channel` and `update_thread` (internal changes with undo) |
| `chat` | the real `post_message` and `send_dm` (speaking elsewhere or for someone; a routine's run never gets them) |
| `blocks` | the real `show_block` and `start_poll` (ADR 0113), next to `create_artifact` and the Drive's other tools |
| `missions` | a `propose_mission` with the real description and findings schema (no computer: the proposal is only recorded) |
| `memory` | the agent's memory items (found with `search_context`) |
| `fixtures` | per tool name, canned results: the first entry whose `when` words all appear in the call's input (no `when` = default) |
| `expect` | deterministic: `investigate`, `mustCall` (`"a\|b"` = any), `mustNotExecute`, `approval`, `evidence` (any of), `noReply` (routine cases: true = nothing reported, false = a report delivered, by `hand_off` or as the final text of a routine that reports every time, and posted), `ask` (`never`/`required`), `mustNotCall`, `notTriggered` (other agents' handles the trigger must not start), `receipts` (act with undo: receipt kinds the reply must carry, e.g. `issue.created`), `missionFindings` (`propose_mission` with read/data findings and at most one decision), `approvalWhy` (every approval request carries a reason of 40+ characters for its card), `handOffs` (`{ "from>to": n }`: exactly n notes between those two, by handle), `personSees` (`maxAgentMessages` the agents' messages in the case's conversation, `noteLines` its "Nota de…" lines), `maxAgentRuns` (all agents' runs, or `{ handle: n }`), `reported` (a `note` case: whether what came of the note went back to its sender); judge: `behavior` (what a good answer does), `rubric` (extra criteria; with steps or colleagues that run, the judge reads the whole conversation after the trigger), `skipJudge` |

Checkers are unit-tested in `test/behavior-checks.test.ts`; `test/behavior-eval.test.ts` runs the harness with the fake provider (no network).

### Hand-offs between agents (ADR 0095)

`handoff-before-delete`, `status-while-colleague-works`, `note-announces-work`, `nested-handoff-one-report`, `fyi-note-no-report` and `colleague-cannot-finish` run agents working together: colleagues that really run, production's judge for how they work together (Jev, the cheap model without `TYPESAFE_API_KEY`), and production's depth backstop. On every prompt change run `bun run eval:mentions` and `bun run eval:behavior --only <these> --repeat 3` with `--lang pt` and `--lang en`; before a release, in all six languages. Each case must pass most of its runs in every language, and the rest of the suite must not regress at `--repeat 3` (the "How you work" and team lines changed with it). About US$ 0.5 to 1 per case and language.

## Resilience eval

`bun run eval:resilience [--only id,id] [--model …] [--repeat 3] [--concurrency 4] [--no-computer]` (ADR 0109):
cases with an obstacle (no dedicated tool, an empty first search, a site that blocks, a dead link, a page that
errors, a missing connector, a teammate holding the information), a real blocker (a code only the person has) and no
obstacle at all. `resilience-cases.json` adds to a behavior case `web` (the fake web: search results by words, pages by
address, `behavior-fakes.ts` `fakeWebFetch`), `facts` (words the answer must have), `never` (words an invented answer
would have), `blocker` and `maxCalls`. API-brain cases run the real engine path with the real turn-end judge; a
`"brain": "claude_code"` case runs this computer's `claude` headless with the agents' prompt rules and our web tools
over MCP. It prints the success and give-up rates and the cost per success; `--repeat` passes a case on a majority.
