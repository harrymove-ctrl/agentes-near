# 0074. Who answers a message nobody mentioned: the chain

- Status: Accepted (built: the engine, the runner's `brain.route`, the shared client's receipts and status; the screens follow)
- Date: 2026-10-27
- Amends: ADR 0013 (failures and strategies), ADR 0034 §4 (agents' messages), ADR 0059 §5 (a personal plan answers its owner)
- Code: `packages/engine/src/router.ts` (`routeMessage`, `smallModelFor`, the rules), `packages/engine/src/router-jev.ts` (`routeChain`), `packages/engine/src/router-plan.ts` (`planSignInsOf`, `createPlanRouterStrategy`), `packages/engine/src/ai-status.ts` (`orgRouting`), `packages/providers/src/catalog.ts` (`router`, `leastThinking`, `routerModelOf`), `apps/server/runner/brain-route.ts`

## Context

A message that @mentions nobody went to one strategy: Jev when the installation had its key, else a model on the default key's provider, with the outbox retrying a failure. A self-hosted workspace whose agents think only with Claude or ChatGPT plans had neither, so the router failed with "no key": the message showed "No agent will answer" with no reason, and after a reload nothing at all. The fallback model also thought before it answered (Haiku 5.5 has thinking on by default), which made it slow, and a workspace whose default key was Kimi's routed every message with its large model.

## Decision

1. **The steps, in order:** Jev, a small model on any of the workspace's keys, the author's own plan, rules in code, and nobody with the reason. A step that isn't available is skipped without a call (no key, no small model, no sign-in). A step that fails (an error, a timeout, an answer that isn't JSON) is noted in the decision's `error` (`jev: TypeSafe answered 529`) and the next one runs, in the same job. Routing never goes back to the outbox: the rules always end it.
2. **A small model** is a provider's routing pick (`router: true` in the catalog): its fastest model with the least thinking, at about US$ 0.0006 a call or less, which is not always its `cheap` one. Claude Haiku 5.5, GPT-6 Luna, Gemini 3.5 Flash-Lite, DeepSeek Flash, GLM-5.3 Flash and MiniMax M3. Kimi has none (its cheapest model always thinks), and coding plans never route. The order: the workspace's own `router_model` when its provider has a key, then the default key's provider, then any other key (Claude, OpenAI, DeepSeek, Gemini, Z.ai, MiniMax), then the server's own Claude key. It is asked with `effort: "none"` (the least thinking the model allows, `leastThinking`: off where it can be turned off, `minimal` on Gemini 3.5 Flash-Lite, `low` elsewhere), 512 output tokens (2,048 for a model that can't stop thinking) and 8 s.
3. **A plan picks only for its owner's own messages,** personal or team seat alike, since plans are personal, and only on a self-hosted server: it is off on the Cloud, where Jev is ours. It runs through the runner's `brain.route` (protocol 24) with every CLI tool off, nothing of the folder or its owner loaded, no session kept, in a temporary folder, as the agent's own user, killed after 30 s. Only plan sign-ins count: a sign-in the person made and lent to one of their own agents, never a coding plan's key, or the computer's own Claude Code sign-in where the person paired that computer and it is signed in with a plan (`claude.ai`; Codex doesn't say, so its own sign-in doesn't count). Never on a computer that won't run the route: Windows for now, or one where that CLI is switched off. One route per sign-in at a time, and none while that sign-in has a process open (a turn, or the one kept after it): the runner answers `busy` and the author's next sign-in, else the rules, decide. A turn or a task that starts on that sign-in meanwhile stops the route first, and the rules decide that message. It is skipped where a reply or a lone agent already decides. `message.routing` says "Picking who answers" before the call. Its usage is recorded on the plan (kind `router`, its computer and account) at no cost.
4. **Rules, in code:** R1, a reply to an agent (a quote, or a reply under its message where no other agent spoke). R2, the channel's one agent when the author is the only person there. R3, the agent of the author's own previous exchange within 10 minutes (they addressed it, or it answered them), when the message names no other person of the workspace (a whole first name, any case and accent). Not "whoever spoke last": that agent may have been answering someone else.
5. **Every decision is stored with every candidate** (score 0 when nobody), the step that decided (`strategy`: `jev`, `llm:<model>`, `plan:<kind>`, `rule:<name>`, `none`) and the earlier steps' failures. `message.routed` carries `decidedBy`, the message list's receipts carry it and `mention_needed`, so a receipt survives a reload. `ai-status` says who picks for the workspace (`routing.by`) and for the person asking (`routing.mine`), and whether the workspace has an API key.
6. **An agent's own message** goes through Jev or a model only: never a plan, never a rule.
7. **The LLM judge** uses the same small model with the least thinking. No plan answers a judge question: they come from the system, not from one person.
8. **Only code writes the follow-up marker:** a decision's `reason` starts with `follow-up` when the policy keeps the person with the agent they talk to, and a step's own words come after its name (`jev: …`, `model: …`, `plan: …`). The reply policy reads only a leading marker, so no model can take an agent's right to stay quiet.

## Consequences

- On a self-hosted server a workspace with only plans routes its people's own messages and every reply, and no decision disappears on reload.
- The plan step spends the author's plan limits and waits out an agent's live process. Its worst case, with every step failing, is 40 s (2 + 8 + 30).
- The Cloud must have core's own Jev key before this ships there, or it routes by small models and rules only.
- Claude's API and OpenAI's are taken at their word on turning thinking off for Haiku 5.5 and GPT-6 Luna. A refusal is a provider error, and the chain moves on.

## Alternatives considered

- **A plan picking for everyone's messages.** Plans are personal, and Claude's terms keep their limits to ordinary, individual use.
- **The channel's only agent whatever the company.** With several people and one agent, every greeting would wake it.
- **Kimi's large model as the small one.** About US$ 0.009 and several seconds a message: no routing beats that.
- **Skipping the prompt cache on router calls.** It saves a quarter of the input of a call that costs a fiftieth of a cent.

## Addendum (2026-10-30): the rules read a person's messages in a row

A run of a person's messages, each within 2.5 s of the one before and each one the router decides on itself, is decided once, on its last message (ADR 0013, addendum of 2026-10-30, §2), so the rules see it as one message too. R3 reads whom the person speaks to: it stays out when the message, or the same person's messages right before it, name a person of the workspace ("boa tarde walter", then "como esta hoje"). R1 holds for a quote reply to an agent followed by more messages of the same person.

## Addendum (2026-10-31): R4, the team's coordinator

After R1 to R3, R4 sends a person's message nobody could read to the team's coordinator (ADR 0093), only when the person is alone in the channel with the agents and the message names no person. When a step could read it and the policy picked nobody, the coordinator takes it too, if it needs an agent or the person is alone with the agents. Both are stored as `rule:coordinator`. A message the step heard speak to one agent (`addressee`, below) goes to that agent instead, stored as the step's own pick, and to the coordinator only when it is the one spoken to. When the policy picked nobody and the person last talked to one agent (below) that still clears continuity's bar (`continuityMinScore`), that agent takes it before the coordinator, as the same run it may pass. A message the coordinator took (`rule:coordinator`) is no talk with it: the walk for the agent last talked to skips it like a message routed to nobody, or the generalist would pull every later pick back to itself.

## Addendum (2026-10-31): the agent a message speaks to answers

In #general, with no @, "ada pergunta pro theo ai qual meu email mais recente pls" went to Theo: Jev scored him 0.90 and Ada 0.52 (needs 0.78, best @theo), since each agent's question said yes when the message "asks it or anyone something its role and what it can do cover", and Theo has the email. The message speaks to Ada; Theo is only the one she should ask.

1. **Who a message speaks to** is one rule in every step's words (`SPOKEN_TO`): the agent it asks to answer or to act, by @, by name or by its role, never one it only names as someone to ask, involve or hand over to, or only talks about. A follow-up that names another agent only that way still speaks to the agent the person was just talking to: right after Theo spoke, "pergunta pra Ada se o PR subiu" is Theo's. The rule's own examples name no agent of the eval, so no case passes by recalling them. Each agent's Jev question says yes for the agent spoken to even when what it asks needs another agent (it can ask that one), weighs its role and what it can use only when the message speaks to no agent in particular, and says no for an agent the message only names while it speaks to another. Jev's tie-break Choice (`best_agent`) and the small model's prompt read the same rule.
2. **An addressee question,** asked only of a person's message among two or more agents (`asksAddressee`). Jev answers a Choice, "which agent does `latest_message` speak to?", over the candidates (name, handle, role) and `none` (a person, anyone, every agent, a follow-up that names nobody). The small model and a plan give `addressee` first in their answer, a handle or `none`, and it counts only then too. From 0.6 for one agent (`SPOKEN_TO_THRESHOLD`; the small model's answer counts as 1) that agent is the decision's `addressee`, Jev's words name it (`to @ada (0.86); best @theo …`), and `withAddressee` folds it into the scores: an agent scores at most the probability that the message speaks to it or to no agent in particular, and the agent it speaks to at least that probability times the need for any agent. Below 0.6, and for a message to every agent (`for_everyone` from 0.5), the scores stand: capping every agent without lifting one would leave a message the Choice only leans on to nobody. With that day's answers and a Choice of 0.86 for Ada (assumed: the real Jev hasn't answered it yet), Ada scores 0.67 and Theo 0.14.
3. **The rules after the step don't undo it.** For a person's message the addressee is who they talk to now, in place of the agent that spoke last: it gets the continuity bar, a short follow-up goes to it, and "clearly another" is measured against it. It takes a reply (quote or thread) from the agent replied to only when the router picked it; otherwise the reply stays with that agent, as before ("isso do deploy é com a ada" under Theo's report is Theo's). When it is picked the message goes to it alone and the decision starts with the follow-up marker (§8), so it may not pass. An agent's message has no addressee (§6: another agent comes in only past its own bar, which the floor would lift), nor does a channel with one agent (it keeps its `pass`), and the rules of §4 have no step to hear one.
4. **It can consult the agent named.** The agent spoken to runs for the person and `ask_agent` is a core tool. The agent it names got no run of its own for that message, so `ask_agent` doesn't take the question for a request that agent is already answering: the consultation goes through and the person sees it.
5. **An eval,** `bun run eval:router` (`packages/engine/eval/router.ts`): 42 cases through the real `routeMessage` on Jev or, with `--step llm`, the small model, in Portuguese, English, Spanish, German, Japanese and Arabic, each with exactly who answers. "Ada, ask Theo…" goes to Ada, "Theo, …" to Theo, "can someone…" to whoever can, and "someone tell Theo…" to Theo, whose news it is. A quote or thread reply to Theo that hands over to Ada stays with Theo, one that speaks to Ada goes to her; right after Theo spoke, "ask Ada…" is still Theo's; a message to a person or to the room that only talks about an agent goes to no agent. A message to every agent, small talk and follow-ups as before. Manual, like the other evals; its cases and harness run in CI with a fake Jev.

## Addendum (2026-10-31): the agent a person last talked to

In #private, with Theo (PM) and Ada (Dev), a person asked "ada quanto ta seu limite de uso?" (routed to Ada, who answered) and, 23 minutes later with nothing said in between, "me de bom dia todo dia ás 8:30 da manha". Either agent could create that routine. It went to Theo, 0.63 to Ada's 0.55 (needs 0.54, `jev: best @theo (confidence 0.83)`): past continuity's 10 minutes nobody was `agent_just_talking`, the Nouls were about even (0.576 each, if the Choice gave Ada 0.12), and the tie-break Choice decided. The person expected Ada.

1. **The agent last talked to.** For a person's message among two or more agents that is no reply to an agent, has no addressee and names no person: the one agent their latest message to an agent went to, read newest first in the same conversation (the channel's main timeline, or the thread with the message it is under: another thread is another conversation) within what the router reads (`ROUTER_SLICE`: 30 minutes and 12 messages). A message went to whom it @mentioned; else to the agent the router sent it to (`routing_decisions.selected_agent_ids`) once that agent answered after it or while a run it started is still at work, so an agent asked by name and still at work counts and one that passed or failed was never talked to; else, never routed, to the first agent that answered it. One that went to no agent ("valeu", or a question the agent sent it passed on) doesn't end the talk, nor does one decided with the person's next message (`continued`), which went where that one did. One that went to several agents is no one's, and one the router hasn't decided on yet, still unanswered, leaves it unknown. Read newest first, an agent addressed since takes over. There is none when the message, or the person's messages right before it, name another agent ("theo me de bom dia…"), also when the step isn't sure the message speaks to that agent. Within continuity's 10 minutes (§4) it counts only when the agent just talking is that same agent: when another agent spoke since, today's follow-ups decide, as before.
2. **It only settles a pick between agents that could do it.** When the router picks one other agent and the agent last talked to clears its own bar (`minScore`, no lower) and, on its own, the need check (`needs_agent` from `minScore`, or its own clear pick), the message goes to the agent last talked to alone, marked `follow-up; last talked to` (§8: it may not pass). Unless it clearly fits another agent better: by the scores (at least `clearPickScore`, 0.8, and 0.3 over it, the bar a follow-up already has), or by the step's tie-break. Jev weighs which agent's role and apps fit best in its Choice (`best_agent`), which moves two agents' scores apart by at most 0.1; the step now reports it (`RoutingResult.best`), and from `CLEAR_CHOICE` (0.9) a Choice for another agent keeps the message there. In its test, "cria uma task pro sprint de amanhã com os itens do roadmap" after a talk with Ada, with Nouls of 0.9 for Theo and 0.75 for Ada (she can create tasks too) and a Choice of 0.95 for Theo, the PM, goes to Theo, though their scores (0.96 and 0.72) are under 0.3 apart. That day's 0.83 doesn't count; in that workspace Jev's only Choices above 0.9 (19 decisions with one, 2026-10-30 and 31) were clear in the scores too, 0.99 and 1.0 to 0.6. The small model has no Choice: its scores decide. When the router already gives the message to the agent last talked to, gives it to nobody, or to several (a message to every agent), nothing changes, and the agent may pass. An agent's message (§6) has none. The step isn't told: `agent_just_talking` keeps its 10 minutes, and the rule reads the step's answer after it.
3. **Why 30 minutes and 12 messages:** it is what the step reads, so code doesn't act on an exchange the step can't see. A pause of up to half an hour is still the same talk, from its first minute; an exchange hours old, or buried under a busy channel's newer messages, never wins over a clear fit, and inside the window a clear fit still does. Continuity's 10 minutes would have missed this case.
4. The eval has the day's case 23 and 5 minutes after the talk, and a request that clearly fits another agent's role 23 minutes after a talk with Theo (`pt-last-talked-to`, `pt-last-talked-to-soon`, `pt-last-talked-to-clear-fit`; 45 cases).

## Addendum (2026-11-01): a message for the agents always gets one (R5)

About 7 of 74 routed person messages in a day got no agent. In a channel with two people and two agents, a person wrote to the agents as a group ("I did it all myself on my own computer, you all got tangled up"), five minutes after a talk with one of them: Jev said nobody (`needs_agent` 0.3, `best` that agent at 0.46). Their next "Got it?" got nobody too. Neither the addressee rule nor the agent last talked to changes that: both only redistribute a pick, and the coordinator (ADR 0093) waits for `needs_agent` ≥ 0.5. A failed chain was silence unless the person was alone with the agents.

1. **R5, after the policy and the duplicate check.** A person's message with no mention that nobody was picked for, that is no reply to a person by name (`toPerson`), not already answered by another agent, and not an ack (at most 4 words, no "?", `needs_agent` under `DEFAULT_NEED` 0.25: "valeu", "ok", "👍" in any language, with no word list; a person alone with two or more agents is exempt, as ADR 0093 has it: "bom dia!" there is for the team), gets exactly one agent when it is for the agents:
   - **addressed:** the step heard it speak to one agent (`addressee`), which takes it as the step's own pick; or `for_everyone` ≥ 0.5, or `needs_agent` at the pick gate (0.5, ADR 0093's bar), also right after a colleague spoke;
   - else, unless **people talk among themselves** (`toPerson`, a quote reply to another person, a thread under another person's message no agent spoke in, or another person's message right before it within `PEOPLE_WINDOW_MS`, 5 minutes): the person talks with an agent (the agent replied to, the agent last talked to, or the agent whose message is right before theirs within continuity's 10 minutes) and asks something (a "?"), or `needs_agent` ≥ `DEFAULT_NEED`, or the person is alone with two or more agents.
2. **Who:** the agent they talk with (reply, last talked to, just spoke), else the team's coordinator, else the best placed agent: Jev's Choice `best` at any confidence when it names a candidate, else the top score even under `minScore`, ties to the agent that spoke here last, then the oldest agent. The coordinator comes after the agent the person talks with, as "preferring the one the person was talking to" asks.
3. **Recorded as:** strategy `rule:default` (the coordinator keeps `rule:coordinator`), decided by `{ step: "rule", rule: "default" }` (the receipt: "Ninguém foi chamado, então o Caio respondeu" / "Nobody was called, so Caio answered"). The reason starts with `follow-up; default; talking to` for the agent talked with (`reply-policy.ts` reads it as addressed: it may not pass), `coordinator; default`, or `default; best` (an ordinary router run, which may pass). Two picks of the agent talked with drop the leading `follow-up` and may pass: an ack from a person alone with the team, and a failed chain's fallback (nobody read the message). Alone with the channel's one agent (R2), R5 stays out: the step decided knowing it.
4. **Noise guard.** One agent per message, never several. A default pick is no talk: the last-talked-to walk skips `rule:default` decisions as it skips `rule:coordinator`, so one bad pick doesn't pull every later message to that agent. At most `DEFAULT_PICKS_PER_HOUR` (6) default picks per channel in a rolling hour; past that, nobody. Budgets are unchanged.
5. **A failed chain is never silence** (amends §4): when a step tried and failed (an error, a timeout; not when every step was skipped for want of a key or a sign-in, which stays `mention_needed`), after R1 to R4, a person's message that people aren't talking about among themselves and that isn't a short ack (at most 4 words, no "?") goes to the agent they talk with, else the coordinator, else the agent that spoke here last, else the oldest agent, under the same hourly cap, in a run that may pass. The cap bounds an outage at 6 runs per channel an hour.
6. **Measure it.** `strategy = 'rule:default' or reason like 'coordinator; default%'` counts R5 picks; the share of passes among `default; best` runs is the noise metric. Alert above 15% of router runs a day.
7. The eval has `pt-default-complaint`, `pt-default-followup-question`, `pt-default-people-talking`, `en-default-to-room` and `pt-default-ack` (50 cases), checked in CI on a fake Jev that gives every agent too little.
8. **Talking with an agent is no reason on its own.** "vou almoçar agora, volto em uma hora" or a long thanks 15 minutes after a talk needs nobody; without a "?" the agent talked with needs `needs_agent` ≥ `DEFAULT_NEED` like any other. `DEFAULT_NEED` 0.25 is the spec's fallback: on three days of production (25 nobody decisions on person messages), 12 nobody decisions sat under 0.2, 1 between 0.2 and 0.3 and 5 between 0.3 and 0.5, against 11 picks between 0.2 and 0.3, too few to confirm the bar; revisit it with the R5 share after deploy.

## Addendum (2026-11-03): the receipt doesn't name the AI that picked

The receipt's last line said "Escolhido pelo Jev", "Escolhido pelo Claude Haiku 5.5" or "Escolhido pelo seu plano do Claude". People who don't know what Jev or a small model is read it as noise. `deciderOf` now returns a line only for a rule's pick ("Uma resposta para a Ada", "Só a Ada responde aqui sem menção", "Segue a conversa com a Ada", "A Ada coordena o time", "Ninguém foi chamado, então a Ada respondeu"), on the web and the phone. The decision is still stored and sent as before (`decidedBy`, `routing_decisions.strategy`); only the words are gone, in every language.

## Addendum (2026-11-10): an answer to an agent's question reaches it

A short answer to an agent's question ("pode sim") reads like an ok: the step hears no need for an agent, and R5 skips an ok, so the yes reached nobody. Now, when the latest message of the conversation (the channel's main timeline, or the thread with its root) that isn't the person's own is an agent's that mentions them and asks something (a question mark), within `ASKED_REPLY_WINDOW_MS` (2 hours), the person's next message there is a reply to that agent, as a quote reply is (`repliedAgentId`): it goes to that agent whatever the scores, marked `follow-up`, and R1 decides it when no step can read it. A message from anyone else in between ends it. An agent that needs an answer before it goes on still asks with `ask_user`, whose card holds the run and resumes it; a question in the text no longer gets lost, it starts a new run with the conversation.

## Addendum (2026-11-10): a rule never answers for the step

The reply rule (a quote or thread reply to an agent, a short follow-up) picked the agent whatever the step heard. A thread reply that only @mentioned another person, with a need the step scored near zero, went to the agent that answered last, which asked what the person needed; an "ok, I'll wait" under an agent's update got a run that reacted and wrote a line too.

1. **People first.** A message that @mentions people and no agent is for them: no rule gives it to an agent, and none answers (`for people` in the decision's reason). Only an answer to an agent's own question to this person (the addendum above) still goes to that agent, and never one that is nothing but the mentions.
2. **An ok gets a reaction.** When the step hears the message as purely social (`social.react`, else `isAck`: a few words, no question mark, little need), the agent a rule or the step would pick gets no run; it reacts instead, with the step's emoji (`held back`). Not when that agent's last words in the conversation asked something: then an ok is an answer.
3. **No agent needed.** A follow-up the rule alone picks, for a message the step needs no agent for (`needsAgent` under `NO_AGENT_NEED`, 0.1), gets nobody, and R5 doesn't pick one after it. The same two exceptions hold.
