# 0089. Agents keep going until the work is done: stretches, not turn caps

- Status: Accepted (built: the server, the web and the phone app). The release waits on `bun run eval:mentions` in six languages. Amended 2026-10-31 by ADR 0095: §5 (the 15 minutes run only while nobody works on a question or hand-off) and §6 (a wake-up held inside an agents' DM shows its card where the agent that asked works)
- Date: 2026-10-31
- Amends: ADR 0008 (the hop limit becomes a depth backstop), ADR 0034 (an agent's mention is no longer limited to once in a row; §4's chime-in rule stays), ADR 0037 round 3 (the promise word list, `follow_up`'s hop bound), ADR 0048 (notes' hop rule and the acknowledgement rule), ADR 0053 §1 (how far a chain stays a person's), ADR 0056 §5 (`run.hop_limit`); by its addendum, ADR 0049 (a run another agent's mention woke may pass)
- Code: `packages/engine/src/stretch.ts`, `dispatch.ts` (`startOrJoinRun`), `jobs.ts` (`delegatedAgents`, `stretch.paused`), `judge.ts` (`mentionNeedsNothing`), `messages.ts` (`MessageAuthor`, `receiptsFor`, `unreachedAgents`), `reply-policy.ts` (`byAnotherAgent`), `run-resume.ts`, `consultations.ts` (`noteReply`), `follow-through.ts`, `executor.ts` (`oweAnswer`, decisions a person made), `cancel.ts` (`mayStopRun`), `continue-run.ts`, `no-ai.ts` (`answerNow`), `authority.ts`, migration `0139_agent_stretches`, `packages/client/src/lib/action-cards.ts`, `packages/client/src/realtime/receipts.ts`, `apps/web/src/components/StretchCard.tsx`, `apps/mobile/src/features/ai/StretchCard.tsx`, `packages/engine/eval/mention-handoff.ts`

## Context

Agents stopped long before the work was done, and nobody saw why:

- An agent's @mention woke another agent only once in a row (`hop >= 2`, `agent_chain_cap`): when Ada answered Theo and asked him something back, Theo never heard it.
- Notices, `ask_agent`, `tell_agent` and follow-ups woke a run only below hop 4 (`NOTICE_WAKE_MAX_HOP`), and `AGENT_MAX_HOPS` was 3, so a CI check came back twice and then never.
- Two rules read words: the follow-through check ran only after an English, Portuguese or Spanish promise list matched, and a reply to a note under 40 characters without "?" was dropped (short Chinese or Japanese answers, the Arabic "؟").
- The authority chain stopped at 8 links: about 9 steps in, a person's work counted as nobody's and lost the tools that need one, such as asking other agents.

## Decision

1. **A stretch: the work agents do on their own since a person last acted on it.** Each message and run carries `stretch_id` next to `hop` (migration 0139, nullable: on older rows the row is its own root). A person's message is a root, and so is work nobody asked for (a routine's report). A message a run writes takes that run's hop and stretch from its row in its own insert (a person may have rerooted the run meanwhile); one no run wrote (a notice, a task's end, a follow-up line) states its stretch, which `MessageAuthor` requires when `runId` is null, so no path slips out of the count. The runs a person's message starts carry that message's id.
2. **Any person action starts a fresh stretch.** A run that reads a person's message (`oweAnswer`), or resumes on what a person decided (an approval, an answer to its question, a secret), gets hop 1 and a new stretch, in the row and in memory (`rerootRun`). Another agent's answer resuming a run is no person's action. "Continuar" under a stopped reply or a reply at its step limit (ADR 0015), and "Parar e mandar", start at hop 1 in a new stretch. Waiting costs nothing: there is no time limit.
3. **Jev decides intent only, in any language.** `mentionHandoffs` reads every agent an agent's message mentions, also when it opens with "@name", together with the message being answered (the trigger of the author's run, its first 1,000 characters). Handing back work the other agent asked for, or asking it something back, is a hand-off; thanks, acknowledgements, agreement and sign-offs are not, even addressed to it. Only with no judge, or when it fails, does "@name first" count by itself. The prompt's line about the other agents says a mention wakes that agent, so agents mention one only to hand it work or ask it something, never to thank or confirm.
4. **Code decides safety, reading no words** (`stretchStop`, in `startOrJoinRun`, which every run start passes through: after the join attempt, for a trigger at hop 1 or more that is not a routine's background run or a granted run):
   - at most 50 runs at hop 2 or more per stretch (`STRETCH.runs`), or 10 when an agent wrote the stretch's root (`STRETCH.unattendedRuns`, work nobody asked for);
   - each agent at most 20% of its monthly budget (`STRETCH.budgetShare` of `effectiveAgentBudget`) in workspace-billed usage on its own such runs. A plan costs the workspace nothing, so the run count is a plan agent's limit, under the plan's own usage window;
   - a wake-up whose run already exists (a redelivered event) is never held.
   On a stop nothing starts (callers already read null as nothing started) and the `stretch.paused` job posts the card, once per stretch, message and agent. `ask_agent`, `tell_agent` and `follow_up` check the same limits before acting and refuse with "You and the other agents did what you may do on your own since a person last wrote. Tell the people here what is done and what is left. They can let you go on.", and their card's Continuar wakes that agent again, on the card. When the limit is the spend of the agent the tool would wake, the card names that agent, whose budget it is.
5. **What stays.** The cap of model calls per run (a backstop of 200 since the ADR 0015 addendum of the same day, with runs that go in circles stopped long before), each agent's monthly budget and the plans' limits, consultations' chain, cycle, 15-minute and same-note rules (since ADR 0095 the 15 minutes run only while nobody works on it: a colleague still at it gets more time), follow-ups' bounds, and chime-ins only from a first answer to a person (ADR 0034 §4). `AGENT_MAX_HOPS` stays as a depth backstop, default 100 (at most 500): the stretch limits stop agents long before, so reaching it means some path lost its stretch, and it records the operator event `run.hop_limit`.
6. **One card, with Continuar.** One `meta.actionCard` of kind `stretch_paused` per stretch (its writers take an advisory lock on the stretch alone, as the no-AI card's do, and a wake-up held later joins the paused card found among the channels of the stretch's runs, since the ways a wake-up is held place it in different conversations; a wake-up with no message of its own, a refused tool's or a mission's keep-going, joins only a card in its own channel and keeps its thread, so Continuar starts it where it was working), written as the agent the work stopped at, where the work would have gone on (for a run in the agents' private DM, where the agent that asked works; a wake-up `startOrJoinRun` holds inside that DM is placed there too, with `peopleRun`, ADR 0095). It lists the held wake-ups, the reason and the limit, with a `bodyCode` (`stretch_paused_runs`, `stretch_paused_spend`) so each person reads it in their language, with no step count: "Ada e Theo pararam para checar com você antes de continuar", or for the spend "Ada parou para checar com você · usou 20% do orçamento do mês". The person behind the work hears of it (in-app and push), or the routine's creator when nobody asked. Continuar is `POST …/messages/{id}/answer-now` on the card, for who asked, the agents' owners or an admin, the same people as Continuar under a stopped reply: the card moves from paused to continued once (compare-and-set; pressed again it starts nothing), each held wake-up whose agent is still in the conversation starts at hop 1 in one fresh stretch (an agent already at work there takes it in that run, which goes on at hop 1 in the new stretch, and the message it takes moves to that stretch too), and it is audited (`stretch.continued`). The card then folds to one quiet line, "Ana deixou continuar · 14:32" ("Você deixou continuar" for who pressed it). Who asked is the person behind the work (`messageRoot`), on the card and on every run of the stretch: on a run another agent woke, they may also press Parar, Continuar under its reply and Responder agora (`mayStopRun`). Money shows only to people who can see costs; everyone else reads the percentage.
7. **Only mentioned.** On an agent's message, the mentioned agents the judge did not pick are `referenced` in its receipt (the list and `message.routed`), and the web and the phone show receipts on agent messages that mention agents: "Só mencionado", and on the web "Chamar um agente" beside it. An agent the judge picked and a limit held is the card's to explain.
8. **The two word rules go to Jev.** The follow-through check asks the judge once at the end of every conversation run, in any language; only when it reads work left undone does it look for something set to wake the run (`wakesLater`, read only then), and the nudge quotes no sentence. A reply to a note goes back when the judge reads it as asking the sender something or giving it something to act on (`noteReplyMatters`); with no judge, or when it fails, it goes back, and the stretch limits bound what that wakes.
9. **The authority chain.** `MAX_AUTHORITY_CHAIN` goes from 8 to 1000, and `messageRoot` remembers each message's root for a day (`caches.messageRoots`: a message's links never change), so a long chain stays the person's at the cost of its newest link.

## Consequences

- Agents work together for up to 50 runs they start on their own per person action, about 25 review-and-fix rounds, or 12 hours of a CI check every 15 minutes. Hitting it costs one click, and the card says why. Each run stores its stretch (indexed on `agent_runs (org_id, stretch_id)`), so the real sizes are one query away: the numbers can be tuned, or become a workspace setting.
- One more judge call at the end of every conversation run, and one for an agent's message that opens with "@name" (it skipped the judge before). The judge's mistakes are bounded by the limits, and its misses show as "Só mencionado".
- Wake-ups in parallel can read the count at once and pass it by one step's fan-out.
- A self-hoster who set `AGENT_MAX_HOPS` low keeps a low depth limit in front of the stretch limits.
- The release waits on `bun run eval:mentions`: hand-backs, questions back and courtesies in Portuguese, English, Spanish, German, Japanese and Arabic. It passes only when no courtesy scores 0.6 or more and every hand-back and question back does.

## Left for later, measured with stretch ids

- Stopping on "nothing new was done", once runners report Claude Code's own tool calls: the server can't see them today, so it would pause real coding pairs, and talk-only work after a few turns.
- A plan-share limit, from the runner's usage reports.
- Loops through email or webhooks (`Auto-Submitted`, the events an agent caused itself): they open new stretches today.
- "Chamar um agente" on the phone's receipt sheet, and the budget share in money on the phone's card.

## Addendum (2026-10-31): an agent's mention wakes unless it needs nothing

§3 asked "is this a hand-off to act on now?" and woke at 0.6. In production that dropped work the named agent needed, silently, until a person pushed (cases anonymized as in the eval): a handover document delivered to an agent (0.58), a review verdict whose last line handed its summary to the agent waiting for it (0.16; that agent later said it had stayed quiet), and "I'll ask @agent to review it" said to the person, which never reached the reviewer. Agents now work by default, as long as they don't act, reply or spend when nothing needs them.

1. **The question is what must not wake** (`mentionNeedsNothing`, judgment `mention_needs_nothing`, in place of `mentionHandoffs`): does the message need nothing from this agent? Nothing is a thanks, an "ok" or 👍, agreement, a sign-off, a quote or a name ("as @x said", "@x already deployed", "talk to @x"), or a plan or offer that waits for a person. Work, a request, an assignment, a question, a delivery to read or act on (a file, a handover, results, a summary, a verdict, a review, also in the last line of a long message) and "I'll ask @x to…" with no person to decide first need it. It still reads the message being answered, in any language.
2. **Only a confident "nothing" skips.** The mention wakes the agent when the chance it needs it (1 − "nothing") is at least `MENTION_WAKE_THRESHOLD`, 0.2: the agent stays asleep only when the judge is at least 80% sure the message needs nothing. Before, it slept whenever the judge was less than 60% sure of a hand-off, so at 41% "nothing" already. The costs are uneven: a missed hand-off is lost work nobody sees until a person asks, a needless wake is one turn that ends in `pass` with nothing posted, so a skip has to be at least four times likelier to be right than wrong, and a clear courtesy is not borderline for a calibrated judge. The handover (0.58 hand-off, so about 0.42 "nothing" read the old way) wakes at the new bar; the verdict (0.16, about 0.84 read the old way) would not by the bar alone: the new question, which names a summary and a verdict as needing the agent, is what wakes it, and the eval holds it to that. `ROUTER_MENTION_THRESHOLD` keeps its scale (the chance the message needs the agent), default 0.2 instead of 0.6, so a server that set 0.6 keeps about the old bar. `routing_decisions` keeps the names (`mention-jev`, `mention-llm`) and records that chance as each candidate's score. Without a judge, or when it fails (a timeout, an outage), only "@name first" counts: waking every agent named while the judge is down lets two agents thank each other in a loop.
3. **The agent it wakes may stay quiet** (`byAnotherAgent` in `replyPolicyFor`): a run another agent's message woke by mention (trigger `mention`, hop 2 or more) may `pass`, like one the router brings in, and reads its own "# Why you were called": do what the message hands you, and "I'll ask @you to…" with no person to decide first is the request itself; on a thanks, an ok, a sign-off or a name, pass at once without looking anything up. A pass posts nothing, so it mentions and wakes nobody. A person's mention, a DM, a consultation, the agent's own lines (notices, a task's end, a follow-up), a person's click on that message (Continuar on a pause card, "Responder agora": hop 1 in a fresh stretch) and a run a person wrote into still answer. On Claude Code and Codex the pass is the bridge's `pass`, the same as on the API (conformance scenario 15).
4. **No second judge before a computer turn.** The mention judge already runs before the run exists, with the message and what it answers, so the same question again before a Claude Code or Codex turn would cost a judge call on every wake and change nothing. The cheapest pass is one turn that calls `pass` first: on the API one model call with the agent's full context (memory retrieval included); on Claude Code and Codex a CLI turn, which also makes the CLI's own closing call after `pass`. The judge's score doesn't reach the run.
5. **Thanks loops** stop at the judge (a thanks back needs nothing) and, when it misreads one, at the woken agent's pass. The stretch limits stay a backstop, not the guard.
6. **Notes** (`tell_agent`) already wake their recipient every time, in the note's own transaction (`createAgentRuns` in the agents' DM), for the person behind the sender's run: the note carries the sender's run (`agent_run_id`), which `authority.ts` follows, so the recipient's computer turn gets `work` when a person is behind the sender. Only the stretch limits (`refusedAtLimit`), the same note within an hour, and an archived agent, one outside the person's audience or one with no AI hold one back; runs nobody is behind can't send notes (ADR 0053 §2). Unchanged.
7. **A mention of an agent that isn't in the conversation** reaches nobody (mentions resolve to members only). The message keeps those agents (`meta.unreachedAgents`, from `unreachedAgents` in `messages.ts`, written by the executor's `post`; not in an agents' DM, where mentions wake nobody anyway), and the author's next context reads a line after it: "[Not delivered]: @vera wasn't in this conversation, so your mention didn't reach it. If you meant it to act or answer, use tell_agent or ask_agent, or add it to this conversation with add_agent_to_channel (it works with the rights of the person you work for)", without the last part in a DM, which keeps its participants. Only under the author's latest message with text: once it writes again the request is settled one way or another, and an old line would make it act on it in an unrelated turn. Past tense and "if you meant": a mention may only name an agent the author already asked another way. `post_message` and `send_dm` say it in their result.
8. **Tests.** The fake judge answers "nothing" (1) for an agent's mention unless a test says otherwise (`createFakeJudge`), so a canned reply that names an agent wakes nobody by accident; tests that hand off say so.
9. **Eval.** `bun run eval:mentions` asks the new question at the new threshold and adds the production misses (anonymized) and "as @x said". The release waits on it, with Jev and with `--judge llm`.

Not done: the apps don't show "not delivered" under a message yet (the meta is there for them), and a mention that reached nobody doesn't wake its author: the line waits for its next turn.

## Addendum (2026-10-31): both sides, every day

Agents act and wake by default, but should not act when they don't need to: that annoys people and wastes tokens. Both sides are measured in production every day, instead of learned from customers' reports.

1. **The report** (`autonomy-report.ts`): one read-only statement per range of UTC days, per active workspace (held, suspended or deleting ones only when asked for by id). Stalls: an agent's @mention that started no run (the judge's "only a reference" left out, never one it failed to read; one a stretch's limit held counts with its pause card); runs the policy kept from tools for who was behind them (read-only) or refused a tool for that; promises the follow-through judge found unkept, and those that ended after the nudge without acting; notes, questions and reached @mentions unanswered in 30 minutes; a run at its step limit or told to wrap up near it, a limit's failure (steps, budget, stuck), paused stretches and missions their stuck guard paused; a person's message meant for agents (a mention, a DM with an agent, the router's pick, a channel message the router never decided on) with no word from that agent in 10 minutes; background tasks that failed in their first minute. Their total counts each stall once (an ignored promise is one of the unkept ones). Noise, in conversation runs: ended without a message, replied to only a thanks, an ok or a sign-off and did nothing else, woken by an agent's @mention and did nothing (no message, or only an acknowledgement), with their tokens and cost. Each event goes on one side: a message or a hand-off whose woken run ended done without a word (it passed, or only reacted) is that run's noise, never also an unanswered stall, so the two totals never move together on the same runs.
2. **Computed from what is stored**, except two marks in rows runs already write (no migration): the run's first `context` step lists the tools the run's policy kept from it for who was behind it (`heldBack`, from the Tool Gateway's listing): what actually limited the run, not who was behind it, so the count follows the policy as it changes (a run nobody is behind that works with every tool isn't read-only); each `model_call` step of a computer turn counts the calls the computer ran itself (`executed`: Codex's commands and file changes; Claude Code keeps its own on the computer, and our tools it calls through the bridge have steps of their own), the only sign that such a turn acted rather than talked. What counts as acting is any tool call but reacting, passing, the agent's status line, a tool directory's search and loading a skill: a look-up counts, since it is often what was promised or asked ("I'll check the logs"). Runs from before have neither: their read-only count is their refusals alone.
3. **Delivery.** `OPS_REPORT_EMAIL` (off by default, on a self-hosted server too): the workers queue `ops.autonomy_report` for the day before, due at 01:00 UTC so the last messages had their answer window, once per day by its dedupe key; it emails the day's totals against the daily average of the 7 days before and the five workspaces with the most stalls and the most noise, names and counts only. `bun run report:autonomy [--day YYYY-MM-DD] [--org <id>]` prints the whole table.
4. **Limits.** An acknowledgement is a word list in SQL, in several languages and scripts, never a yes or a go-ahead; a judge can read the short triggers if it misses too much. An answer is any word in the conversation from the agent the message was for (any agent in a DM, or for a message nobody decided on), the talker's quick reply included. A question's outcome is its status: closing stamps `answered_at` whatever came of it. A channel message the router never decided on counts as meant for agents only with `ROUTER_ENABLED`.

## Addendum (2026-11-10): a mention is credit or a reference, not a request

Waking unless the judge was 80% sure of "nothing" made channels loud: an agent answering a person named another in passing ("via @x", "the numbers are from @x", "I asked @x"), the judge was unsure, the named agent woke and answered the person a second time or corrected the first in public, and its own mention woke the first again. Agents ask each other with `ask_agent` and hand work with `tell_agent`, which come back by themselves.

1. **The question asks for a plain request.** `mentionNeedsNothing` keeps its judgment name, but "nothing" now covers credit, a source, what the agent did, said, sent or was asked, agreement, a correction, a thanks and a plan to ask it later ("I'll ask @x to review it"). Only a request, a task, a question addressed to it or work handed to it needs it.
2. **Only a confident request wakes.** `MENTION_WAKE_THRESHOLD` and the default of `ROUTER_MENTION_THRESHOLD` go from 0.2 to 0.6; `DEEP_MENTION_THRESHOLD` from 0.6 to 0.85. An unsure judge leaves the agent asleep, and the receipt says "Só mencionado".
3. **An agent the run already asked isn't woken again.** A mention of an agent the same run consulted or handed work to (`agent_consultations.asker_run_id`) wakes nothing, for every run, not only a routine's: the consulted agent answers the agent that asked, never the person too.
4. **The woken agent and the prompt.** `WHY_AN_AGENT_CALLED` tells the woken agent to do only what it was asked, never to answer the person's question again, restate, confirm or nitpick, and to tell an agent that erred privately with `tell_agent`. The channel's line about the other agents says to ask with `ask_agent` and `tell_agent`, never to restate another agent's answer, and to add only the new part with a link to its message.
