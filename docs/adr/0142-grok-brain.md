# 0142. The Grok brain: agents think with a person's Grok plan through Grok Build

- Status: Accepted (2026-11-04; amended 2026-11-04 by ADR 0143, Gemini through Antigravity built; built: runner, engine, server, the shared client, the web and the phone app). The flags in §2 and §5 are read from Grok Build 1.0.34's own docs and `--help`, not yet run against a signed-in plan: the probes in §8 come before it ships.
- Date: 2026-11-04
- Extends: ADR 0032 (computer brains), ADR 0041 (accounts per agent), ADR 0053 §3 (permission profiles), ADR 0059 (AI accounts belong to people), ADR 0114 (the Cursor brain, whose shape this mirrors), ADR 0137 §4 (the team's right hand on a plan)

## Context

xAI ships Grok Build, a coding CLI (`grok`), "in early beta for all SuperGrok and X Premium Plus subscribers" (x.ai/news/grok-build-cli). It signs in with the person's xAI account by browser OAuth or a device code, runs headless (`grok -p`), and its `streaming-messages-json` output is Claude Code's `stream-json` shape: a `system`/`init` line listing every tool and MCP server, `assistant` and `user` lines, a `result` with usage. The owner asked for Grok plans next to Claude's, ChatGPT's, Cursor's and OpenCode's.

What the CLI does, read in its bundled docs (`docs/user-guide/02-authentication.md`, `05-configuration.md`, `07-mcp-servers.md`, `14-headless-mode.md`, `18-sandbox.md`, `22-permissions-and-safety.md`, `26-config-reference.md`) and `grok --help` / `grok login --help` of 1.0.34, run with the network denied (2026-11-04):

- Everything lives in `GROK_HOME` (default `~/.grok`): `auth.json` (0600), `config.toml`, sessions, its leader socket.
- `grok login --device-auth` signs in with a device code; `grok logout` signs out. No status command: `grok models` prints "You are not authenticated." first when signed out.
- `config.toml` (`[mcp_servers.<name>]`, stdio or URL, `${VAR}` interpolation, `bearer_token_env_var`) is where MCP servers go: the `GROK_CONFIG` overlay drops `mcp_servers`, and a project's `.grok/config.toml` needs folder trust and stops at the git root.
- It reads Claude Code's and Cursor's MCP servers, rules, skills, agents and hooks unless told not to (`GROK_CLAUDE_*_ENABLED`, `GROK_CURSOR_*_ENABLED`), sends telemetry (`GROK_TELEMETRY_*`) and updates itself (`GROK_DISABLE_AUTOUPDATER`). There is no `--no-auto-update` flag.
- Headless only: `--tools` (built-ins allowed; the MCP meta-tools `search_tool` and `use_tool` stay), `--disallowed-tools` (wins; `Agent` blocks subagents), `--no-subagents`, `--disable-web-search`, `--no-plan`, `--permission-mode`, `--allow`/`--deny` rules (`MCPTool(server__*)`), `--sandbox <profile>` (which also keeps tool calls in the process instead of a shared leader), `-r <id>` to resume.
- The model reaches MCP tools only through `use_tool` with the qualified name `server__tool`.
- Usage on `result`: `input_tokens` (uncached), `cache_read_input_tokens`, `cache_creation_input_tokens`; cost is often missing on OAuth traffic.
- Its installer also links `~/.local/bin/agent`, Cursor's binary name.

## Decision

1. **A sixth computer brain** (`BrainKind` `grok`, `BRAIN_NAMES` "Grok Build", `BRAIN_PLAN_NAMES` "Grok"), the same `brain.turn` as Codex and Cursor (`GrokBrain` in `brains/codex.ts`, `GROK_CLI`). Runner protocol 43 (`GROK_PROTOCOL`): `brain.turn` `kind: "grok"`, `account` `kind: "grok"`, `hello.executors.grok` (the version line and `grok models`), `access.tools.grok` (absent: follows Codex's, like Cursor's and OpenCode's). Missing CLI: `grok_missing`. No live steering: `brain.steer` answers `unsupported`. Usage is the person's plan (tokens recorded, cost zero), limits and sign-in failures by Grok's words (`plan_limit`, `not_logged_in`).
2. **One `grok -p` per turn** (`brain-grok.ts`): `--output-format streaming-messages-json --include-partial-messages --sandbox workspace`; `work` is `--permission-mode bypassPermissions` (writes in the turn's folder only), `plan` is `dontAsk` with `--allow MCPTool(agenteschat_agentes__*)` and edits denied; `--model`, `--effort` (`xhigh` and `max` as `high`), `-r` for a chat it knows. Its lines go through Claude Code's parser (`ClaudeStreamParser`); calls to `use_tool`/`search_tool` are our bridge's and aren't repeated as `tool_call`. Our session → Grok's session (from `init`) is kept per account in `grok-chats.json`; a new chat leads its prompt with the engine's context, and a resume Grok can't find starts a new chat once.
3. **Always an account.** `GROK_HOME` is the account's folder; its `config.toml` holds our MCP server alone (stdio `agentes-runner mcp` with the run, token, socket and home from the env, or the bridge URL with `bearer_token_env_var`), rewritten when it differs, so the turns of several agents on one account share one file. `agentes-runner mcp` with neither `--run` nor `--task` takes the run from `AGENTES_MCP_RUN`. A turn without an account is refused (`not_logged_in`): the computer's own `~/.grok` would need our bridge in the person's own config.
4. **Accounts** (ADR 0041, 0059): a device-code sign-in in a new folder (`grok login --device-auth`, the first https URL on x.ai or grok.com and its code, `parseGrokLogin`), status from `auth.json` and `grok models`, `grok logout` on removal. One login per agent; never made for all agents where each is its own OS user (`sharesSignIns` false, as Cursor's). Every Grok process gets `GROK_QUIET_ENV` (no Claude Code or Cursor config, no managed MCP or gateway tools, no telemetry, no self-update, memory forced off since an account's turns of several agents and Lodi share it); `XAI_API_KEY` and every `GROK_` variable of the runner's env (folder trust, memory, managed config, sandbox, sign-in, the chat proxy URL) never reach it, and `XAI_`/`GROK_` are reserved secret names. The `workspace` sandbox lets a turn's shell write in `GROK_HOME`, so before every turn the runner removes what a later turn would load as trusted outside every tool and the chat guard (`GROK_PLANTED`: `managed_config.toml` with its hooks, MCP servers and plugins, the folder-trust store `trusted_folders.toml`, the user `lsp.json` and `plugins/`); the sandbox itself keeps `hooks/` read-only, `config.toml` is rewritten, and `requirements.toml` counts only signed.
5. **The team's right hand** (ADR 0137 §4) on a Grok plan: `--tools search_tool,use_tool`, every built-in the docs name also in `--disallowed-tools` (`GROK_CHAT_DENIED`, `Agent` included), `--no-subagents --disable-web-search --no-plan --permission-mode dontAsk --allow MCPTool(agenteschat_agentes__*)`, in an empty folder with none of the agent's secrets. The guard (`grokChatBreach`) kills the process on an `init` listing a tool but the meta-tools (or our qualified names) or a server but ours, on anything before `init`, on a tool block that isn't a meta-tool (a `server_tool_use` web search included, checked as the block starts), and on a `use_tool` whose qualified names aren't all ours: the turn ends `tools_not_locked`. xAI keys (`xai-…`) join `scrubSignIns`.
6. **Apps.** Plan choice `grok` (`PLAN_BRAIN`, after OpenCode), the Grok mark, the device code step on the web and the phone (the phone's "Seu plano" lists Grok with Claude and ChatGPT), its models in "Quem pensa" (what `grok models` listed, else `GROK_BUILD_MODELS`), the tool switch in Ferramentas. The desktop app adds no Grok accounts yet, as with Cursor's.
7. **Terms.** "Atende outras pessoas" on a Grok plan shows the same line and ⓘ as Claude's ("Grok plans are for personal use. Letting other people use yours is a gray area in Grok's terms."), wherever that switch is: under the plan in Connect AI, the agent's page, Settings › Lodi. xAI's consumer terms couldn't be read (behind Cloudflare); xAI itself advertises headless runs "inside scripts and automations".
8. **Before it ships**, on a Linux computer with a signed-in SuperGrok account: the `init` tools under the chat flags (the shell's id, whether `--tools` takes the meta-tools), whether the account brings grok.com gateway connectors into a session (the guard stops them), whether `config.toml`'s `${VAR}` reaches a stdio server's `env`, the plan-limit text, `grok login --device-auth`'s output without a terminal, whether a work turn in a repository with its own `.grok/` starts headless without a trust grant, and what a `use_tool` call's input looks like (the guard reads the qualified names in it; another shape stops every Lodi call).
9. **Install**: the core installs no coding CLI. Self-hosters run xAI's installer (SELF_HOSTING.md; under `/opt/grok` and linked into `/usr/local/bin` in system mode); the Cloud image pins a release binary as `/usr/local/bin/grok`, with a runner of protocol 43. On a computer with Cursor's CLI too, Cursor's `agent` is linked last.

## Not done

- **Gemini plans through Antigravity's CLI (`agy`)**: built since in ADR 0143 (the owner chose personal plans behind a plain warning, Gemini Enterprise and the API key, 2026-11-04). What follows was the reason it waited: Google's FAQ says wrapping `agy` inside third-party applications "is not supported under consumer plans" and "can result in suspension or termination of your account", which is a stated rule, not a gray area; `agy` also documents no sign-in command a runner could drive, no way to move its config folder per account and no deny-all for its tools. Gemini already thinks through the model brain with an API key, the route Google recommends. Waiting on the owner: Gemini Enterprise sign-ins only, consumer plans behind a plain warning, or neither.
- The computer's own Grok sign-in; Grok's plan usage (shown only in its TUI); live steering.

## Consequences

- A Grok plan thinks for its owner's agents on any computer whose runner is 43 or newer with Grok Build installed, and for Lodi locked to its tools.
- Everything Grok-specific is behind runner protocol 43 and `kind: "grok"`: older runners and servers never see it.
