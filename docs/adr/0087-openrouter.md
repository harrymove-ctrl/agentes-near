# 0087. OpenRouter: one key for many makers' models

- Status: Proposed
- Date: 2026-10-31
- Extends 0007, 0012 and 0018.
- Code: `packages/providers/src/openrouter.ts`, `packages/providers/src/catalog.ts` (`modelInfo`, `listedModels`), `packages/engine/src/gateway.ts`, `packages/engine/src/credentials.ts` (`openRouterInUse`, `pickerModels`, the key check), `packages/engine/src/auto-model.ts` (`orgAutoModels`), `packages/engine/src/management.ts`, `packages/db/src/schema/agents.ts` (`organization_settings.auto_models`), `apps/server/src/routes/app/agents.ts`, `apps/server/src/routes/app/management.ts`, `packages/client/src/lib/providers.ts`, `packages/ui/src/components/SearchSelect.tsx`, `packages/ui/src/brand/marks.ts`, `apps/web/src/components/AgentFields.tsx`, `apps/web/src/components/AutoModels.tsx`

## Context

People without a Claude or ChatGPT plan often have credit at OpenRouter and want to bring that one key. The API-key providers were a fixed catalog: each model, price and tier written in the code. OpenRouter serves hundreds of models from many makers behind one key, in OpenAI's Chat Completions format. Its public model list (no key needed) gives each model's prices, context window and supported parameters. Prices change, models come and go, and each response reports what the call cost.

## Decision

1. **A provider whose models come from a list.** `openrouter` joins `PROVIDERS` with its own protocol. Its models are read at run time and kept beside the catalog (`setListedModels`); `modelInfo` and `listedModels` read both, so every catalog helper (costs, windows, tiers, the routing pick) works on either. A catalog id never has a slash and an OpenRouter id always does (`maker/model`), so the id names its provider before the list is read (`modelProvider`).
2. **Which models.** From `GET /api/v1/models?sort=most-popular&limit=1000`: the ones that call tools on Chat Completions (`endpoints`, `supported_parameters` with `tools`) and answer in text, with a known price of zero or more, a window of at least 32,000 tokens (a smaller one can't hold an agent's prompt), an id that looks right (`^~?[a-z0-9][\w.-]*/[\w.:-]+$`, up to 100 characters) and a name of up to 120; at most 2,000. OpenRouter's own routers (`openrouter/*`, no fixed price) and the batch variants (no endpoint) are out. The list is outside data: every field is checked.
3. **Prices.** USD per token becomes nano-USD per token, rounded up after rounding to a pico-USD. A missing cache price is the input price. Output pays the dearer of completion and internal reasoning. An override above a prompt size is `longContext`. Time-of-day and weekday overrides fold into each price's highest, so budgets err high. An alias (`~maker/family-latest`) takes the dearer of its own prices and its target's.
4. **The list in memory.** No copy is stored and no key is used to read it. The server reads it only while some workspace has an OpenRouter key that isn't revoked (`openRouterInUse`): the pickers' routes, the gateway (once a key resolved), the executor, routing and the AI status ask for it only then. A read is waited for only when there is no list, or when a model isn't in a list over a minute old. Otherwise a list over an hour old answers while one read refreshes it. A failed read isn't tried again for a minute. Saving a key starts the first read.
5. **Calls.** Chat Completions through the OpenAI SDK at `https://openrouter.ai/api/v1`, streamed, with attribution that names the product (`HTTP-Referer: https://agentes.chat`, `X-OpenRouter-Title: agentes.chat`), never a self-hosted server's own address. The system blocks are one system message. Claude's ids get cache breakpoints (`cache_control` on the cached blocks and on the request); the other models cache a prompt's prefix by themselves. Tools go sorted by name on every call, tool results as `tool` messages. `effort` becomes `reasoning.effort` at the nearest effort the model lists. `none` turns thinking off where the model allows it, else asks for the least it takes: a model whose reasoning is mandatory refuses `none`. `reasoning_details` come back as one `opaque` block and are sent back unchanged in tool loops; another provider's opaque blocks are dropped. `outputSchema` becomes a strict `json_schema` with `provider.require_parameters`, so only upstream providers that honor it answer. There is no `data_collection` override: the account's own privacy settings at OpenRouter decide.
6. **Cost and budget.** The reservation before a call is its worst case at the listed prices, with the output capped at the model's `max_completion_tokens`. The recorded cost and the spend are OpenRouter's `usage.cost` for that call, plus the upstream provider's `upstream_inference_cost` when the person's own provider key served it (BYOK); without a reported cost, the listed prices of the model that answered. Tokens are recorded as for the other providers: the prompt less its cached and written tokens, cache reads and writes, and the completion (reasoning included). A stream that ends without a usage chunk is estimated and priced from the list. A call that OpenRouter routes to an upstream provider dearer than the listed price can spend past its reservation; the counter takes the reported cost.
7. **Errors,** in the words of the other adapters: 401 a refused key, 402 no credit left (not retried), 403 refused, 408, 429 and 5xx retried. A failure inside the stream (an `error` chunk after HTTP 200) is read by its code and retried when it is an outage, with what had arrived. A model OpenRouter no longer lists fails its call with a message that says so (a run's error `run.model_unlisted`, with the model). With no list yet, the call is an outage and is tried again. Neither is "no AI": the AI status asks only for the key, and the call checks the list.
8. **The key on save.** `GET /api/v1/key` with the key, no model call: a refused key (`provider_key_invalid`) or a management key (`provider_key_management`) is never stored. When OpenRouter answers neither way, the key is stored. Rotating a key checks the new one.
9. **Pickers.** The good picks come first (`pick: true`), each a family's `~…-latest` alias so the set doesn't age: GLM (medium, suggested), DeepSeek Flash (small, cheap), GPT Luna (routing and the judge), Claude Sonnet (large), DeepSeek Pro, Gemini Flash and Claude Haiku. A pick OpenRouter stops listing is skipped. The agent's model picker is a search over every model (`SearchSelect`), OpenRouter's good picks before the rest of its list, each with its price. Criar agente shows the good picks only. A workspace without an OpenRouter key sees only the good picks, each saying a key opens it. The model routes send `pick` and the default `tier`; the apps never call OpenRouter.
10. **Automático.** On an OpenRouter key the tiers map to the picks: small DeepSeek Flash, medium GLM, large Claude Sonnet. A workspace changes them in Configurações › Chaves (`organization_settings.auto_models`, `{ openrouter: { small, medium, large } }`): each one of OpenRouter's listed models, null puts a tier back on its default. A chosen model OpenRouter no longer lists falls back to the default, and the dialog shows that tier on its default. Before the list is read no tier maps: the run, and summaries on that key, wait it out as an outage, never on another provider's model.
11. **Claude Code through OpenRouter: not now.** It works through OpenRouter's Anthropic-compatible endpoint, but each turn would spend OpenRouter credit outside the Model Gateway, with no agent budget and no recorded cost, and OpenRouter guarantees it only on Anthropic's own models. It would fit the coding plans' key accounts (ADR 0059 §8), with usage read from `GET /api/v1/key` and only keys that carry an OpenRouter credit limit.

## Considered and not chosen

- `/api/v1/messages` with the Anthropic adapter: two translations for every model that isn't Claude, and the SDK drops `cost`.
- The Responses API: stateless, and its docs show no cost in usage.
- A copy of the list in the database: a second source of truth for prices that change.
- `/api/v1/models/user`: it needs each workspace's key, for a list that is the same for everyone.

## Consequences

- The same budgets, usage records and audit as the other providers. Listed prices show on screen and make the reservation; the reported charge is what gets recorded.
- A server whose workspaces never add an OpenRouter key never contacts OpenRouter. One with a key reads the public list about once an hour while it is used, and up to once a minute while runs ask for a model the list lacks.
- A model OpenRouter delists fails its agent's next run with a clear message until someone picks another.
- Imports keep catalog models only: an OpenRouter model needs the workspace's own key.
- The phone has OpenRouter's key, mark and words; models and tiers are chosen on the web and the desktop app.
- To confirm on the first real call: whether `prompt_tokens` includes cached and written tokens (taken as in OpenAI's format), and whether streamed `reasoning_details` arrive in pieces (merged by index).
