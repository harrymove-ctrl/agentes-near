# 0099. Several accounts per connector

- Status: Accepted (built: the server, the shared client, the web and the phone app)
- Date: 2026-10-31
- Amends: ADR 0016 (the same address again replaced the account signed in)
- Code: `packages/engine/src/connectors/custom.ts` (`storeCustomConnection`, `accountFrom`), `connections.ts` (`toolPrefixOf`, `toolPrefixOfConnection`, `freeToolPrefix`, `freeLabel`, `checkLabel`, `renameConnection`), `oauth-mcp.ts` (`serverKey`), `presets.ts` (`account`), `listing.ts` (`offersCatalog`), `mcp.ts`, `access.ts`, `approvals.ts`, `agent-proposals.ts`, `tools/directory.ts`, migration `0140_connector_accounts`, `apps/server/src/routes/app/connectors.ts`, `connectors-custom.ts`, `packages/client/src/lib/connected.ts`, `apps/web/src/components/Connectors.tsx`, `ConnectFlow.tsx`, `ConnectorCatalog.tsx`, `apps/mobile/src/features/connectors/ConnectionScreen.tsx`, `ConnectSheet.tsx`

## Context

Connecting a second account of an MCP server replaced the first one's sign-in: the server found the connection by its address (`connector.custom_reconnected`), so the grants given for the first account applied to the second, and nothing said so. Two connections of one server would also have exposed the same tool names: the gateway keeps the first tool of a name, and a provider refuses a tool list with duplicates.

## Decision

1. **An MCP server takes several accounts** (one-click presets and servers by address). Its address again is another account (`outcome: connected`). Addresses match as the apps match them (`serverKey`, the apps' `sameServer`: no trailing slash, any case). `connectionId` ("Reconectar") gives that account a new sign-in or key in place, at its own address only (400 `connector.other_server`), carried through OAuth by `oauth_states.connection_id`; its name, tools and grants stay. Catalog connectors keep one connection each (GitHub's git proxy and repository list assume one): connecting again is a new sign-in (`reconnected`). A server with no sign-in, connected again, is the connection it has.
2. **The provider says which account.** A preset may name a read-only tool that lists the accounts a sign-in reaches (`account: { tool, list, id, name }`). Stripe's is `list_available_accounts_or_orgs` (`{ accounts: [{ stripe_context, livemode, name }] }`: its sign-in offers only the `mcp` scope, no OpenID, and may reach a live account and its sandboxes), not the `get_stripe_account_info` its docs name. What one sign-in reaches is one account here: its ids with their mode, sorted and joined (`account_id`), so grants given for test data never move to live money. It is asked with the fresh credentials before anything is stored, and again whenever the tools are listed (`account_label`; `account_id` is set once, and an answer for another account names nothing). The same account again only refreshes its sign-in (`same_account`). "Reconectar" signing in to another account is refused (409 `connector.other_account`) and changes nothing: the grants were given for the first one. When the provider can't say which account a Reconectar reached, it is refused too (409 `connector.account_unknown`, try again). Accounts stored before their provider was asked are asked when another account of that server comes in. An account the provider doesn't name can't be told apart: it comes in as a new one, and its name step makes a duplicate easy to spot.
3. **The label is the account's name**: "Stripe (Acme)" when the provider names it, else "Stripe", "Stripe 2"…, unique among the workspace's live connections (ignoring case). A preset's label is its English name, unique among presets ("Cloudflare (Workers)", "Cloudflare (logs)", "Supabase (read-only)"), and the apps send a catalog entry's own label, so a name nobody changed reads in each person's language, a numbered one with its number. Sign-in copy names the brand alone ("Continuar no Cloudflare"). Admins rename any kind (`PATCH …/connectors/{id}`, 1 to 80 characters, 409 `connector.label_taken`, audited as `connector.renamed` with `from` and `to`). The apps show the label everywhere (`itemName`: Conectores, the agent's page, Quem usa, approvals, the phone). The provider's name shows as "Conectado como" only when the label doesn't already say it.
4. **Tool names never collide and never move.** Each connection keeps `tool_prefix`, set once: a catalog connector's id; for a server's first account, its service's name as a slug (not the account's); a later account follows the server's oldest live account (its prefix without a number), whatever the apps send: `stripe`, then `stripe_2`. A catalog connector's id is kept only for a catalog connector this server offers (`offersCatalog`): Linear without its OAuth app leaves `linear` to the one-click server standing in for it. A partial unique index keeps it unique among the workspace's live connections; a connect that races another for it retries with the next number. Renaming never renames tools, so grants and denials of single tools keep applying. A big connector's directory is named with it (`stripe_2_find_tools`). Tool descriptions and the prompt's "What you can do" use the connection's label (a catalog connector's too), so agents tell accounts apart, and `propose_agent` finds an app by its name or by its service (`stripe`, asking for the name when two accounts match).
5. **Every account is every agent's** (as a first connection is, the ADR 0016 addendum of 2026-10-30). Connecting ends on a short confirmation that says so and how many actions ask in the chat; "Ajustar" there, or "Quem usa" on the connection's row, narrows it per agent. Tool names carry the account's prefix (`stripe_2_create_refund`) and descriptions its label, so an agent with two accounts tells them apart.
6. **What connecting did is said**: `outcome` on the connect calls, the OAuth callback (`&outcome=`) and `oauth/complete` (an older server sends none: the apps read it as `connected`), and `connector_error=other_account`, `account_unknown` or `gone` on the callback. `connector.custom_connected` and `connector.custom_reconnected` carry `label`, `account` and `everyAgent` / `sameAccount`.
7. **migration 0155** backfills `tool_prefix` with today's names (the connector id; the label's slug as `mcp.ts` made it) and numbers duplicates among a workspace's live connections (the oldest keeps its names, a catalog connector first), renaming their `tool:` and `deny:` grants with them. Duplicate labels are numbered the same way ("GitHub 2"). A deploy migrates while the previous version still serves, and a rollback runs it on the migrated database, and that version inserts connections without the column: **migration 0157** adds a trigger that fills it on such an insert as the backfill does (the catalog connector's id, else the label as a slug, numbered past the names a live connection holds), then sets NOT NULL (`-- deploy-safe:`). `toolPrefixOfConnection` keeps naming a row without one as that version did.

## Consequences

- Two accounts of one service are two rows, each with its own agents and levels, on the web and the phone.
- Only Stripe names its accounts for now: other presets get numbered names until their account tool is checked.
- A connection made before this keeps the label it was given, in the language of whoever connected it.
- No prompt rule asks agents which account a person means. Add one if agents act on the wrong account.
