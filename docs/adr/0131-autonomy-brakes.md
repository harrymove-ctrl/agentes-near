# 0131. Autonomy brakes: proactive by default, bounded where nobody asked

## Context

The default-allow direction (ADR 0097 addendum, ADR 0120, 0121) made agents act and wake by default within their permissions. A co-owner then hit three runaway cases in one afternoon:

- **(a) Asked, then went ahead.** An agent ended its turn with "Quer que eu faça?". The turn-end judge's `continue` criteria counted "offered reversible work inside what it was asked ('want me to create the issues?')" as a promise to keep, so the controller told it to go on: it installed packages and ran a 40-file benchmark. The person's "ta fazendo oq ai?", "??" and "ow maluco" got no answer for four minutes (the quick reply runs on the workspace's cheap API model, and a workspace on a Claude plan alone has none, so every try failed silently), until the safety net moved the run to long work and "cancela tudo" stopped it.
- **(b) Alert noise became work.** A routine watching an error tracker posted each error and tagged an agent. The agent tried to fix each one, most of them old or benign (known freeze errors), opened about ten PRs in a loop and overloaded its computer, until the owner shut it down.
- **(c) Cross-project calls.** An agent mentioned another agent that works on a different repository and mixed their contexts; the owner had to add an instruction forbidding it.

Calm waits and calm wakes (ADR 0032 addenda) order and park turns on a busy computer. They never cap how much work starts, nor what it is about.

## Decision

Agents stay proactive: what needs working on gets worked on without anyone asking each time. A source the workspace connected and pointed at an agent (an error tracker's alerts, a webhook, a connector's trigger, a routine a person set up) is work that was asked for: the agent works on real items on its own. What holds it is judgment about the items, not permission: noise goes to a digest (§5), an item already being worked joins that work (§4), repeats stop (§6) and parallel work has caps (§7). These four apply to wakes from a message whose chain doesn't root in a person (`messageRoot`: a routine's report or work, a webhook, an agent's own chain), at an agent's mention and at `tell_agent`. A person's proposal first (§3) is only for costly work an agent starts on its own, which nobody set up (`selfStarted`: an unattended run whose chain roots in an agent's own work). What a person asks, directly or through a chain of agents, is never held by any of them. Cheap proactive steps (answering, reacting, reading, notes, internal changes) stay automatic.

### 1. Asking means waiting

- **The controller.** In `decideTurnEnd`, a conversation turn whose reply ends asking something (`endsAsking`: its last line ends with "?", code blocks and trailing marks aside) that the judge reads as a promise to keep (`continue`) ends `done` with rule `asked`, so no continue nudge can push it into doing what it asked about. Its other rules still apply to a question: one asking for a secret in the chat (`secret`), for what its own means could find (`untried`), or handed by a mention that never reached its agent (`unreached`). A run told to ask (`askPending`) still turns its question into the card. The judge's `continue` criterion drops the "offered reversible work" example and says an ask to the person waits for their answer.
- **The prompt.** The proactivity line of "# How you work" adds: if you asked the person something, wait for their answer: end your turn there and don't go ahead as if they had said yes.
- **Follow-ups.** For unrequested work, `wakeFollowUp` doesn't wake the agent while its last word in that conversation is an unanswered question (`askStillOpen`): the follow-up stays pending and looks again later; it is never canceled for it. A person's follow-ups are unchanged.
- The long-work safety net needs nothing: the run ended.
- No timeout on the wait: the person's answer (or anyone's message) is what moves it, as before.

### 2. A person always hears what a working agent does

The quick reply (`talker.ts`) already answers a person who writes to a working run, from what the run does. When its cheap model can't answer (an error, no API key, too slow), it no longer passes silently: the server posts its own status line (`statusReply`, body code `talker_status`): how long it has worked, what it does now (the agent's automatic status line, `presence.agent.*`) and that it reads the message after this step. Same rate limits and checks as a quick reply (one per run per 30 s, never after the agent answered). A pass on a message that is itself a question ("??", "what are you doing?") posts the status line too; any other pass posts nothing. Live steering on computer brains is unchanged.

### 3. Costly work an agent starts on its own needs a go

- **What is costly** (`costlyKind`): opening a PR or MR (a connector tool named so, or `gh pr create`, `glab mr create`, `hub pull-request`), installing packages (`npm|pnpm|yarn|bun install|i|add|ci`, `pip install`, `uv add`, `poetry add`, `apt|brew|cargo|gem|go install`), and a long run (`long`: more than `LONG_STEPS`, 40, tool calls). Starting long work is already only for runs a person is behind (ADR 0121 `workEligible`).
- **Where** (`costlyGate`): in the Tool Gateway, after the arguments' checks and before approvals, so every brain meets it: API calls, bridged tools, and a computer brain's permission prompt (a refusal is the prompt's JSON `deny`).
- **Whose work**: a routine's own run, and a run a routine's report or work woke (a webhook, a connector's trigger), go ahead: only the hourly PR cap applies to them. The proposal is for `selfStarted` runs, whose chain roots in an agent's own work (an agent deciding by itself to install packages or open a PR outside its standing duties).
- **What it does**: the agent's `never` list refuses; a go (the agent's `costly: go`, its `go` list, or a person's go on this run) passes, PRs within `maxPrsPerHour` (default 3, counted as `pr` signals in the last hour, for every non-person run). Anything else is refused with "a card asks the person responsible; end your turn with one line of what you'd do", and the first refusal per run and kind posts the **proposal card** (`meta.actionCard.kind = autonomy_proposal`) where the run answers, for the agent's owner, notified as that card's person.
- **The card**: Pode fazer (this run), Agora não, by the person it is for; Sempre (remembered on the agent: `brakes.go`) and Nunca (remembered: `brakes.never`) only by the agent's owner or who manages agents, since they change the agent for everyone's work (`POST …/autonomy-proposals/{signalId}`). The decision reaches the run that asked as an agent-only `proposal_result` notice, which wakes it; when that run already ended, the run the notice wakes carries the decision, so its retry passes instead of posting a second card.

### 4–7. One item is worked once, noise waits, repeats stop, caps

Before `dispatchMentions` wakes agents for an agent's or a routine's message nobody asked for, and before a `tell_agent` note from such a run starts its target's run (the note is sent with `deferStart`, then `startNoteRun` once the brakes let it through; a held note closes its row and the sender reads why), `brakeWakes` decides per agent. Its digest and loop stop go where the people are: the message's conversation, or for a note the sending run's.

- **Signature** (`signatureOf`): the item's first link to one item (a path segment with a number: an issue's or an error's page) without query or fragment, else its first line with numbers, ids and hashes taken out, hashed. Only an `alert` (such a link, or a first line that reports a failure) is counted for §4 and §6: hand-offs, questions and recurring reports with a dashboard's link never link or stop. Every outcome is an `autonomy_signals` row (`wake`, `linked`, `digest`, `loop`, `later`; also `pr` and `proposal`).
- **§4 open work takes it** (`linked`): the agent already has an active run woken for the same signature, or a wake on it recorded in the last 5 minutes whose run is still starting: no second run, an agent-only note goes into that run ("reported again: include it in your report"). The check and the wake's record run under an advisory lock per agent and signature, so a burst of one alert starts one run.
- **§6 repeats stop** (`loop`): `LOOP_MAX` (3) wakes on one signature within 24 h: no more runs on it, and one line from the agent where it came in, for its owner ("it came back 3 times in a day; tell me how you want it handled"), once per stop window. The same tool error repeating inside a run is already stopped by `stuck.ts`.
- **§5 noise waits for a digest** (`digest`): one cheap judgment per message (`alert_triage`, kind `work` or `noise` at p ≥ 0.6; no judge or an error is `work`). Noise starts no run; real, new or high-impact items go ahead. Every 10 minutes the worker posts, per agent and conversation whose oldest held item is an hour old, one digest line from the agent, grouped by signature with counts, for its owner (`autonomy_digest`). The digest and loop stop lines (`meta.autonomyNote`) are for a person: the router never routes them to another agent.
- **§7 caps** (`later`): an agent with `maxUnrequested` (default 2) unrequested runs active, or, for work a routine or a webhook started, whose computer has turns waiting for room (`crowdedAgents`; agents' own chains already wait in calm wakes' inbox and ranks), doesn't start new unrequested work: the wake looks again every 2 minutes (`autonomy.later`) for an hour, then every 15 minutes, and after a day it starts anyway. Work held only for room is never dropped, nor put in the noise digest. People-asked work never meets these caps; their runs come first in the computer's line already.

### 8. Who an agent may call

`brakes.callAgents` (`all` by default, `some` with `callAgentIds`, `none`) and `brakes.project` with `otherProjects` (agents with different non-empty projects don't call each other unless allowed). Enforced on an agent's mentions and copies to non-members (`onlyCallable` in the message job: the left-out agents aren't woken and the run that wrote it gets a `wake_skipped` note saying so), on `ask_agent` / `tell_agent` (`reachableAgent` refuses), and in the prompt's "# Your team" (`teammatesFor` lists only callable agents). A person's mentions are not affected.

### Settings

`agents.autonomy_brakes` (jsonb, `{}` = the defaults), read through `autonomySettings` (clamped and filled), shown as `Agent.brakes` and changed with `PATCH …/agents/{id}` `brakes` (fields merged, who manages agents). Web: Configurações → "Trabalho que ninguém pediu" (`BrakesCard`, saved at once). Phone: the agent's edit screen (`BrakesSection`). The defaults keep today's autonomy for normal use: everything a person asks, and cheap proactive steps, are unchanged; only costly unrequested steps ask first.

*Amended 2026-11-07:* defaults are open, admins narrow them. `costly` defaults to `go`: costly work nobody asked for goes ahead within the hourly PR cap and the parallel cap, and §3's card is for agents an admin set to ask first (`costly: ask`). Agents whose brakes were saved before keep what was stored, `ask` included (a save then stored every field). A save now stores only the fields people set (`chosenAutonomy`), so a field nobody chose follows the defaults when they change. `otherProjects` stays off: it reads only once a person gives agents projects, which is that narrowing.

## Consequences

- One extra judge call per agent message nobody asked for that wakes agents (`alert_triage`); mentions between agents in a person's chain skip it.
- Work from a source the workspace set up (error routines, webhooks) opens PRs and installs packages without a card, within the hourly PR cap; the triage, the duplicate link and the loop stop are what keep it from chasing noise. Only an agent starting costly work on its own meets a proposal card.
- Signatures are heuristics: two different errors with the same first line and no link share one; the same error worded differently gets two. The loop stop and the digest are per agent and conversation.
- Open PRs on the code host aren't read (no GitHub call): §4 links only to work this server knows (active runs on the signature). A PR the agent opened lately counts through the `pr` cap and the loop stop.
- Not built: the router's agent chime-in (an agent's message with no mention, ADR 0034) and `ask_agent` questions don't pass through §4–7 (a question is answered, not worked; the chime-in is the router's own judgment); the per-computer brake reads calm queue's waiting turns, not the machine's memory or CPU; a duplicate that arrives after the item's run ended is triaged again rather than linked.
- Migration 0184 (`agents.autonomy_brakes`, `autonomy_signals`).

## Addendum 2026-11-02: what a workspace set up is asked-for work

Owner decision: agents are meant to be proactive and work on what needs working on without being told each time. When a workspace connects an error tracker and sends its errors to agents, those agents are expected to fix them; what was wrong in case (b) was chasing noise, not acting. So events from sources the workspace connected and pointed at an agent (alerts, webhooks, connector triggers, routines a person set up) count as requested work: §3's proposal no longer gates them, and the agent proceeds on real issues on its own. Noise triage (§5: known, old, low-impact or duplicate goes to the digest; real, new or high-impact is acted on), the duplicate check by signature (§4), the loop stop (§6) and the parallel limits (§7) decide. §3 keeps applying only to costly work nobody set up or asked for. Scenario S64: an error routine sends 10 alerts, 6 known and 2 repeats of the 2 new ones; the agent fixes the 2 new ones without a card, one PR each, the repeats join that work and the 6 known ones go to one digest.
